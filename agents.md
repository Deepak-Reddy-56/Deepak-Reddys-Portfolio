## Rules

Never delete documentation.

Never overwrite documentation.

Only append to project_log.md.

Never implement multiple milestones at once.

Always produce an implementation plan first.

Wait for approval before modifying files.

Never duplicate logic.

Never duplicate components.

Never duplicate Zustand stores.

Prefer extending existing systems.

Write production-quality TypeScript.

Use React Three Fiber best practices.

Update project_log.md after every completed milestone.

## Development Contract

This project follows milestone-based development.

Every milestone follows the same lifecycle:

1. Read documentation.
2. Understand the current project state.
3. Present an implementation plan.
4. Wait for approval.
5. Implement one milestone only.
6. Update `docs/project_log.md`.
7. Present a summary of changes.
8. Wait for the user to test.
9. Wait for explicit approval to proceed.
10. Commit the approved milestone.
11. Begin the next milestone.

No step may be skipped.

The repository should always remain in a stable, reviewable state.

## Milestone Definition
A milestone is NOT complete simply because the code compiles.

A milestone is considered complete only when:

1. The implementation is finished.

2. project_log.md has been updated.

3. The implementation summary has been presented.

4. The user has tested the milestone.

5. The user has explicitly approved proceeding to the next milestone.

Only after receiving approval may the previous milestone be committed and work begin on the next milestone.

Never begin the next milestone automatically.

Always wait for explicit approval.

## Repository Integrity

Assume every existing file has a reason to exist.

Do not delete, rename or replace files simply because they appear unused.

Before proposing removal of any file:

1. Explain why it appears unnecessary.

2. Explain the impact of removing it.

3. Wait for explicit approval.

Never perform destructive operations without approval.
